## ЗАДАЧА 1. Staff Leader не выдаёт «Administrator»

**Новый файл:** `garrysmod/lua/autorun/server/p11_sv_rankgate_v5830.lua`

Что сделано:

1. **Список разрешённых рангов — в файле, а не в коде.**
   `garrysmod/data/polus_framework/rank_grant.json` создаётся сам при первом старте:

   ```json
   {
     "allow": {
       "staff_leader": ["user","vip","faction_officer","faction_leader","helper","moderator"]
     },
     "deny":  { "staff_leader": ["admin"] },
     "min_level": { "admin": 13, "head_admin": 14, "glava": 16 }
   }
   ```

   Перечитать без рестарта: `p11_rankgate_reload` (Глава Проекта или консоль сервера).
   Показать действующие правила: `p11_rankgate_show` (ранг 4+ / консоль).

2. **«Administrator» закрыт тремя замками сразу:**
   - жёсткий `deny` для `staff_leader` — срабатывает, **даже если ранг дописать в `allow`**;
   - `min_level.admin = 13` — выдавать Administrator может только Chief Curator (13) и выше;
   - `P11FW.CanManageRank(staff_leader, 4)` возвращает `false` — вкладка выдачи в `/menu`
     не предлагает уровень Administrator.

3. **Проверка на сервере, до применения.** Обёрнуты `P11FW.SetRank` и
   `P11FW.CanManageRank` — через них идут **все** пути выдачи:
   - админка `/menu` (act 22 в `fw_sv_setup.lua:317-327`),
   - консоль `p11_rank` (`fw_sv_ranks.lua:103`),
   - любой будущий вызов `P11FW.SetRank`.

   Системная выдача без инициатора (`by = nil`: донат, промо, батл-пасс) не блокируется.

4. **Реакция на попытку:**
   - действие блокируется, ранг не применяется;
   - в чат: `У вас нет прав для выдачи этого ранга`;
   - в лог `garrysmod/data/polus_framework/rank_grant.log`:

   ```
   [2026-08-25 14:45:33] DENY TestPlayer51 [STEAM_0:0:51] tried 'admin' (Administrator) — У вас нет прав для выдачи этого ранга
   ```

   Успешная выдача «чувствительных» рангов тоже пишется в журнал (`ALLOW …`).

**Чем это отличается от v5.8.28 (`p11_sv_rankgrant_v5828.lua`):**
тот файл отмечает «обёртка уже стоит» полем на функции, а в Lua 5.1/LuaJIT
индексация функции — ошибка (`attempt to index a function value`), из-за чего
обёртка v5.8.28 могла не вставать вовсе. v5.8.30 держит флаг в модуле и от
этого не зависит. Оба файла могут стоять рядом — они не конфликтуют.

## ЗАДАЧА 2. Esc в E-меню возвращает управление

**Новый файл:** `garrysmod/lua/autorun/client/p11_cl_escfix2_v5830.lua`

**Корень:** E-меню (`entities/polus_p11_emenu/cl_init.lua:75-81`) делает
`p:MakePopup()` — включает экранный курсор и перехват клавиатуры. Закрывается оно
через `MENU.panel:Remove()` (`cl_init.lua:46-49`), а `Remove()` курсор **не
выключает**. Панель исчезла, перехват остался: WASD не идёт, другие меню не
открываются, выход — Alt+F4.

Что сделано:

1. **Сторож** (`Think`): запоминает полноэкранную подложку E-меню и в момент её
   исчезновения принудительно возвращает ввод —
   `gui.EnableScreenClicker(false)`, снятие фокуса клавиатуры, отпускание
   залипших кнопок (`-attack`, `-attack2`, `-use`, `-speed`).
2. **Esc «в лоб»:** пока подложка живая, на неё навешивается свой
   `OnKeyCodePressed` поверх штатного — штатный обработчик не ломается,
   а ввод возвращается в том же кадре.
3. **Меню паузы больше не блокируется.** Хук v5.8.28
   (`hook "OnPauseMenuShow" → false`) глушил меню паузы — именно поэтому
   Alt+F4 оставался единственным выходом. Он снимается
   (`hook.Remove("OnPauseMenuShow", "P11.EscFix.v5828")`), наш хук возвращает
   `nil`, то есть меню паузы открывается штатно.
4. **Защита от регрессии:** если открыта живая панель с мышью (админка, F4,
   донат — любой DFrame), курсор не трогается. Иначе починка Esc сломала бы
   остальные меню.
5. **Диагностика:**
   - `p11_escdiag` — состояние ввода (курсор, пауза, консоль, живые панели,
     подложка E-меню, число возвратов ввода);
   - `p11_escunlock` — вернуть управление руками;
   - `p11_escfix 0` — выключить сторожа (откат без удаления файла).
