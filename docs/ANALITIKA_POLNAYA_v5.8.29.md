### 2.1 Почему СБОР был мёртв дважды

```lua
-- garrysmod/gamemodes/darkrp/gamemode/modules/p11_sv_sbor.lua:150-153 (как было)
concommand.Add("p11_sbor", function(ply)
    if not IsValid(ply) then return end
    local reason = table.concat({...}, " ") -- concommand args
```

Функция объявлена как `function(ply)` — без `...`, поэтому `{...}` внутри неё в
Lua 5.1/LuaJIT = **«cannot use '...' outside a vararg function»**, то есть
ошибка **компиляции**: GMod не грузит файл целиком. Значит с v5.0.0 не было
ни `/сбор`, ни `!сбор`, ни `p11_sbor`, ни широковещательного баннера — при этом `!сбор` остался
в белом списке чата (`lua/autorun/server/p11_sv_bangfix2_spawn_v5813.lua:45`).
Сверху второй слой: клиентский `p11_cl_sbor.lua` **не включён** в `cl_init.lua`,
то есть экранной части тоже не было. Проверено: файл отсутствует в списке из
55 клиентских модулей.

И **третий** слой, найденный уже прогоном: даже с живым модулем команда из чата
не срабатывала.

```lua
-- p11_sv_sbor.lua:157 (как было)
if string.sub(t, 1, 5) == "!сбор" or string.sub(t, 1, 5) == "/сбор" then
```

`string.sub` в Lua 5.1 режет **байты**. «!сбор» в UTF-8 — это 9 байт, поэтому
`string.sub(t, 1, 5)` возвращало «!сб» и условие не выполнялось **никогда**.
Работала только консольная `p11_sbor`. В `p11_sv_sbor_v2.lua` сравнение идёт по
`#w` байт, плюс защита от пересечения с `!сборка` (это крафт): после префикса
обязан идти пробел или конец строки. Проверено пробой: `!сбор тревога на станции`
объявляет сбор, `!сборка` — нет.

### 2.3 Главная находка: метки на функциях

Прогон в настоящем VM показал то, что не видно глазами. В четырёх autorun-патчах
«уже обёрнуто?» отмечается полем **на функции**:

| Файл | Строка | Приём |
|---|---|---|
| `p11_sv_bangfix2_spawn_v5813.lua` | 63 | `orig.<флаг>` |
| `p11_sv_zz_fixes_v5814.lua` | 46 | `orig.P11_ProfaFix` |
| `p11_sv_rankgrant_v5828.lua` | 54 | `P11FW.SetRank.<флаг>` |
| `p11_sv_jobhp_speed_v5828.lua` | 59 | `POLUS11.ApplyMoveSpeeds.<флаг>` |

В чистом Lua 5.1 / LuaJIT функция **не индексируется**:

```
> local f = function() end
> f.x = 1
attempt to index a function value
> print(debug.getmetatable(function() end))
nil
```

Если движок не ставит функциям метатаблицу, каждый из этих патчей падает ровно
на строке установки метки — и обёртка **не встаёт**. То есть «!профа в любом
регистре» (v5.8.14), «!-команды не уходят в OOC» (v5.8.13), «Staff Leader не
выдаёт Administrator» (v5.8.28) и «ХП/темп профы» (v5.8.28) могут не работать
вообще, при этом в консоли — тишина (ошибка съедается `pcall`/таймером).

**Проверка на живом сервере — одна команда:**

```
lua_run local f=function() end print(pcall(function() f.x=1 end))
```

`false` — патчи не работали; `true` — движок разрешает, и тогда всё стояло.

Новый `p11_sv_funcmeta_v5829.lua` ставит функциям метатаблицу с боковой
таблицей (weak keys), поэтому `f.Флаг = true` и чтение работают как задумано.
Файл грузится в autorun — раньше `InitPostEntity` и раньше любых таймеров, так
что повторные попытки всех четырёх патчей проходят штатно. После этого прогон
показывает `0` ошибок вида «index a function value» (до него их было 30+).

Свои новые модули v5.8.29 от этого не зависят: метки «обёртка уже стоит» они
держат в собственной таблице.

### 2.4 Что даёт (и чего НЕ даёт) имя `darkrp`

- ✅ Сервер виден в браузере/мониторинге как **DarkRP** (`gamemode darkrp`).
- ✅ Файл гейммода: `garrysmod/gamemodes/darkrp/darkrp.txt`, `"title" "DarkRP"`.
- ⚠️ Это **не DarkRP по коду**: `DeriveGamemode("sandbox")`, API DarkRP
  (`DarkRP.*`, `player:setDarkRPVar`, `GM.Config`) в сборке нет. Аддоны,
  рассчитанные на DarkRP, будут сыпать ошибки.
- ⚠️ Настоящий DarkRP рядом ставить **нельзя**: две папки `darkrp` = конфликт.
- ⚠️ В старых патчноутах встречалась инструкция «удали `garrysmod/gamemodes/darkrp/`» —
  она теперь означает «удали чужой DarkRP, наш гейммод живёт в этой папке».
- ℹ️ Внутри игры название осталось прежним: `GM.Name = "POLUS-11 RP"`
  (`shared.lua`) — файл старый, по правилу не правили.
