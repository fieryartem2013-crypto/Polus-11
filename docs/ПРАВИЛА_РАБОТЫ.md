# 📌 ПРАВИЛА РАБОТЫ НАД СБОРКОЙ (обязательны)

> Правило владельца (11.08.2026): «делай ВСЕГДА новые файлы, также если
> маленькие нововведения».

## 1. Главное правило: НОВЫЕ ФАЙЛЫ

**Любое изменение — новый файл. Даже мелкий фикс.**

- Существующие модули НЕ редактируются и НЕ перезаписываются.
- Старые файлы остаются на месте навсегда (как сувениры/архив).
- Новая версия системы = новый файл с версией в имени:
  - `p11_sv_medals_v2.lua` (новая версия вместо старой)
  - `p11_cl_medals_v2.lua`
  - `p11_sv_patch_524.lua` (мелкий фикс)
  - `p11_cl_duty_v2.lua` (доработка)

## 2. Единственное исключение — список загрузки

Чтобы новый файл подхватился сервером, в существующих
`init.lua` / `cl_init.lua` добавляется ТОЛЬКО одна строка:

```lua
-- v5.2.4: новая версия системы X (старая отключена)
"modules/p11_sv_x_v2.lua",
```

При этом старый модуль УБИРАЕТСЯ из списка (или строка комментируется) —
иначе обе версии загрузятся и подерутся за глобальные функции.

## 3. Откат (если что-то сломалось)

1. Убрать/закомментировать строку нового файла в списке загрузки.
2. Старые файлы уже на месте — сборка работает как раньше.
3. Никакой «починки по памяти».

## 4. Сборки

- Имя: `POLUS11_SERVER_vX.Y.Z.zip`
- Версия растёт с каждым пакетом изменений (сейчас v5.2.3).
- Перед каждым пакетом — тег в git (`vX.Y.Z-baseline`) + снапшот-архив.

## 5. Что НЕ трогаем

- «Сувениры» владельца: ЛЕДОКОЛ / РАССУДОК / МЕТЕО / генератор — не загружаются, не удаляются.
- Порядок загрузки ядра — без команды владельца не менять.
- Пуш в GitHub — только после явного «пушим».
